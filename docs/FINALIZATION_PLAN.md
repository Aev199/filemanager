# План финализации (11.10)

Цель: перевести пакеты 1–5 из состояния «код готов» в «проверено в настоящем
окне Windows» и получить итоговый portable EXE. В `main` не вливаем до
завершения шага 4. Все проверки — только на копиях тестовых данных.

## Что проверено перед финализацией

| Проверка | Где | Результат |
|---|---|---|
| Сборка и все тесты workspace | Linux | PASS: 130 core unit + 13 integration + 3 CLI + desktop |
| `cargo check --workspace --all-targets` для Windows | windows-gnu (кросс) | PASS, без предупреждений-ошибок |
| Core-тесты под Wine | Wine | Падения только в Shell API, которые Wine не реализует (ADS, cross-volume move, замена через Корзину, Undo через Корзину) и в `Σ/ς` (CompareStringOrdinal Wine). Нужна настоящая Windows. |
| Окно GPUI: палитра Ctrl+K, «Настройки» Ctrl+, | Xvfb (Linux) | Отрисовка верна; цвета/шрифты Windows не проверяют |
| Windows CI (сборка, тесты, EXE, скриншот) | GitHub Actions run 38124935709 | см. раздел «Результат CI» ниже |

## Исправлено в ходе проверки

1. **Статус закрытого предпросмотра** (отложенный дефект пакета 4): если окно
   предпросмотра закрыто его крестиком или упало, менеджер в течение ~0,5 с
   показывает «Окно предпросмотра закрыто» / «…завершился с ошибкой…» и
   убирает кнопку «Закрыть предпросмотр». `PreviewProcess::exited()` +
   unit-тест.
2. **`\\?\` в путях**: предпросмотр массового переименования, выделение после
   операций и тексты сообщений показывали `\\?\C:\…`; на Windows это ломало
   тест и выделение нового файла. Пути нормализуются, сообщения очищаются.
3. **Палитра в английской раскладке**: `yfcnh` находит «Настройки», `dbl` —
   команды «Вид». Тест в `interface_policy`.

## Шаги финализации

### Шаг 1. Windows CI и EXE (автоматически, ~10 мин)
- [ ] Run на текущем коммите зелёный: check, core unit, CLI, сборка GPUI.
- [ ] Скачать `Filemanager-Windows-x64` (ZIP + SHA-256) и `Filemanager-UI-Screenshot`.
- [ ] Скриншот: тёмная тема, русские подписи, иконки, нет растянутых панелей.
- При красном CI: исправить, повторить только этот workflow (он ручной, без лишних минут).

### Шаг 2. Ручная проверка настоящего окна (пользователь, ~1 ч)
Порядок — по `SMOKE_TEST.md`; минимально обязательный набор:

| Область | Что проверить | Раздел SMOKE_TEST |
|---|---|---|
| Клавиатура | стрелки/Enter/Backspace/F2/Del/Ctrl+C/X/V/Z, Ctrl+K, Ctrl+,, Ctrl+W/T/Tab, адресная строка, русская и английская раскладка | 1.0, 1.0a |
| Мышь | клик/двойной клик, правая кнопка, средняя кнопка на вкладке, рамка выделения, перетаскивание разделителей панелей, перетаскивание окна за заголовок, кнопки свернуть/развернуть/закрыть | 1.0a, 1.3, 3 |
| Цвета | тёмная и светлая тема: текст, иконки, меню, поля ввода, полосы прокрутки, выделение, фокус; масштаб 100/125/150 % | 1.0a, 1.4 |
| Предпросмотр | PNG/JPEG/PDF/Word/Excel/PowerPoint; отдельное окно; **закрытие крестиком меняет статус**; нет provider; >64 МБ; кэш миниатюр | 4 (пакет 4) |
| Файловые операции | копия/перенос/переименование, drag-and-drop из Проводника, буфер обмена с Проводником, Корзина и восстановление | 2, 3, 5 |
| Перенос между томами | второй том (флешка/VHD): сравнение, исходник в Корзину, отмена | 3.3 |
| Конфликты/очередь | «Заменить — прежние в Корзину», «Оставить оба», панель операций | 4 (пакет 2) |
| Массовое переименование | шаблоны, `CON`, `Σ.txt`+`ς.log` (блокировка), Undo, пути без `\\?\` | 4 (пакет 3) |
| Сеанс | настройки и вкладки (включая закреплённые) после перезапуска | 1, 1.0a |

Найденное записывать по форме «Если обнаружена ошибка» в конце SMOKE_TEST:
шаг, ожидалось, получилось, скриншот.

### Шаг 3. Исправление найденного (разработка)
- [ ] Каждая ошибка — регрессионный тест там, где это возможно (core), затем исправление.
- [ ] Повторить только затронутые разделы smoke и один прогон Windows CI.
- [ ] Обновить HANDOFF/MILESTONES: статус пакетов 1–5 → «проверено на Windows».

### Шаг 4. Выпуск
- [ ] Итоговый CI на финальном коммите; сохранить ZIP и SHA-256.
- [ ] Отметить в MILESTONES номер run и хэш коммита.
- [ ] По решению пользователя — PR `feat/native-gpui-foundation` → `main`.

## Известные ограничения (не блокируют выпуск)
- Автор сохранения документа определяется не автоматически (учётная запись наблюдателя + ручной комментарий).
- Нет автопрокрутки при рамке выделения; прокрутка отменяет жест.
- Листание документа в предпросмотре зависит от установленного Windows provider.
- Содержимое старых версий документов не хранится (только метаданные).
