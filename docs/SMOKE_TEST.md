# Проверка экспериментального Filemanager на Windows

**Важно:** этот набор изменений пока не проходил Windows CI. Последняя успешная
сборка относится к более раннему коммиту. Все проверки ниже — **только
на временных тестовых папках** без важных исходных документов.

## 1. Интерфейс

Перед общим прогоном выполнить также UI_POLISH_2026-10-11.md: размеры окна,
DPI, разные ширины split, смена preview role, компактный staging, обе темы.
Затем выполнить ATLAS_ALIGNMENT_2026-10-11.md: глубокая цепочка, horizontal
reveal/resize, 24px marquee, selection/commands/drag в обеих темах.
Проверять новый EXE после UI-доработки, не старый артефакт run №19.

1. В «Загрузках» создай `FM-test-A` и `FM-test-B`.
2. Проверь вкладки, «Разделить окно» (Ctrl+\), список (Ctrl+1) / колонки (Ctrl+2),
   «Назад»/«Вперёд», затем «Сохранить вкладки» и открытие сохранённого
   набора из боковой панели.
3. Закрой программу и открой её заново. Сохранённый набор вкладок должен
   восстановиться. Если одна папка больше недоступна, остальные должны
   открываться.

## Панели со своими вкладками

Старые сеансы восстанавливают до 200 папок (100 прежних разделённых вкладок).
Добавление новых вкладок ограничено 100; восстановленные папки сохраняются все.

1. Открой временную папку. Ctrl+Shift+S добавляет панель справа,
   Ctrl+Alt+S — снизу. У каждой панели своя строка вкладок, кнопки ← → ↑
   и путь; активную панель обводит синяя рамка. Можно открыть до четырёх панелей.
   Перетащи разделитель, затем закрой панель Ctrl+Shift+W: соседние панели
   должны занять освободившееся место. Последняя панель остаётся.
2. Tab / Shift+Tab переключают панели по порядку; Alt+Shift+стрелки — по
   направлению. Ctrl+Tab / Ctrl+Shift+Tab и Ctrl+PgDn / Ctrl+PgUp меняют
   вкладку только активной панели. Ctrl+T / Ctrl+W создают/закрывают её вкладку.
3. Перетащи вкладку на строку вкладок соседней панели: она переезжает туда.
   На содержимом проверь подсветку центра и четырёх краёв. Отпусти на краю:
   появляется новая панель, исходная закрывается, если опустела. Единственную
   вкладку нельзя отделить переносом на край собственной панели. При четырёх
   панелях край принимает вкладку в существующую панель и показывает лимит.
   Во время перетаскивания нажми Esc и отпусти мышь: вкладка остаётся на месте,
   подсветка исчезает. Повтори перенос над строкой вкладок без подсветки.
4. Открой 15 и более вкладок в одной панели. Колесо прокручивает строку,
   переключение показывает выбранную вкладку. Кнопка ⌄ открывает список
   с полными путями; прокрути его и выбери нужную папку. При совпадении имени
   вкладка показывает родителя; наведение показывает полный путь.
   Средняя кнопка закрывает вкладку, двойной щелчок по свободной строке создаёт
   новую. Ctrl+Shift+T возвращает последнюю закрытую доступную папку.
5. Открой одну папку в двух панелях: списки прокручиваются независимо,
   фильтр относится к активной панели. Выделение рамкой не переходит в соседнюю.
   Ctrl+L / щелчок по пути редактируют путь своей панели. Средняя кнопка по
   месту в боковой панели открывает вкладку в активной панели.
6. «Сохранить вкладки» сохраняет всю раскладку. Перезапуск и восстановление
   рабочего пространства возвращают дерево, размеры, вкладки и закрепление.
   Старый сеанс с правыми половинами открывается двумя панелями, все доступные
   правые папки остаются вкладками второй панели. Пропавшие папки пропускаются.
7. Уменьши окно до 760 px, открой панель сведений Ctrl+I, затем раздели вправо:
   при нехватке ширины новая панель должна появиться снизу. Подписи, кнопки
   и список вкладок остаются доступными. Проверь инспектор при смене панели.
8. «Для переноса» теперь Ctrl+Shift+D. Проверь копирование, перенос и Undo
   прежним набором ниже: панели выбирают пути, файловые действия идут через
   прежнюю проверяемую очередь.

## 1.0a. Пакет 5: команды, настройки, закрепление и рамка

1. Ctrl+K или кнопка «Команды»: введи «скрыт фай», попробуй стрелки и Enter.
   В английской раскладке набери `yfcnh`: первой должна быть «Настройки».
   Esc должен закрыть только палитру, сохранив фильтр папки. Ctrl+W/Del внутри
   палитры не должны закрывать вкладку или удалять файл. При отсутствии выбора
   переименование недоступно; при занятой очереди новая папка также недоступна.
2. Через палитру открой «Настройки» (или Ctrl+,). Стрелки выбирают пункт,
   Пробел переключает, Enter сохраняет. Проверь светлую/тёмную темы, скрытые
   файлы, боковую панель и инспектор. «Отмена»/Esc оставляют прежние значения.
   После успешного сохранения стрелки снова управляют списком файлов.
3. Перезапусти EXE: настройки должны восстановиться. На отдельном профиле
   с недоступной SQLite должен быть виден отказ сохранения без применения.
   В светлой теме проверь надписи, иконки, меню, Input и полосы прокрутки.
4. Создай три вкладки; закрепи одну через правую кнопку. Ctrl+W, средняя
   кнопка и «Закрыть другие» должны сохранить закреплённую вкладку.
   Перетащи её; проверь активную вкладку и закрепление после перезапуска.
   Открепи и закрой обычным способом. Повтори после открытия старого профиля.
5. В списке тяни рамку с пустого места снизу или с узкого правого отступа.
   Выбор вверх/вниз должен соответствовать пересечённым строкам. Ctrl добавляет
   к исходному выбору, Esc возвращает его. Перетаскивание с самой строки файла
   по-прежнему перемещает/копирует через прежний механизм, без рамки.
6. Повтори в прокрученной папке с 5000+ файлами и в обеих split панелях.
   Во время рамки измени сортировку/фильтр/вкладку, обнови F5 или прокрути:
   жест должен отмениться, старые индексы не выбирают новые файлы.
   При активном фильтре и смене панели первый клик только фокусирует её;
   начинай рамку следующим жестом и проверь правильные имена. В колонках
   предка сначала активируй нужную папку обычным кликом. Автопрокрутки рамки нет.
7. Сделай снимки фактического EXE: обе темы, палитра, закреплённые вкладки,
   рамка в split. Фактические снимки Linux получены; Windows EXE также требует своих снимков.

## 1.0. Адресная строка и клавиатура

Дополнительная проверка: открой тестовую папку A, затем B; удали A
через Проводник. Кнопка Back должна пропустить уже несуществующую A
и вернуться к ближайшему доступному месту, сохранив рабочую панель.
Кнопка Forward не должна возвращать в удалённую или отключённую папку.
Перед навигацией можно инициировать подтверждение Recycle: при переходе
в другой каталог оно должно сброситься.

1. `Ctrl+L` должен перевести курсор в адресную строку и показать
   текущую папку. Впиши абсолютный путь тестовой папки и нажми **Enter**.
   Проверь, что открылось нужное место и не изменилась соседняя панель.
2. Введи несуществующий каталог: должна появиться ошибка, без
   изменения файлов. Относительные пути не принимаются.
3. Создай две вкладки и переключись `Ctrl+Tab`. `F2` при выбранном
   тестовом файле должен открыть редактор переименования, но не менять
   файл до подтверждения **Переименовать**.
4. `Ctrl+Shift+N` должен показать поле новой папки. Новую папку
   создаёт только явное нажатие **Создать**.

## 1.1. Большие каталоги и плавность интерфейса

1. Создай **отдельную тестовую папку** с 5000 небольших файлов
   (рабочие каталоги не трогать). Открой её в Filemanager: индикатор
   загрузки должен исчезнуть, а затем список должен показывать возможность
   прокрутки **далеко дальше 3000 файлов**, без кнопки Show more.
2. Попробуй прокручивать список и переключать вкладки, пока загружается
   другая большая папка. Окно должно оставаться отзывчивым.
3. Включи **Split**: слева открой большой каталог, справа другой,
   затем переключись в Miller Columns. Файлы левой и правой панелей
   не должны перемешиваться.
4. Пока Filemanager открыт, создай файл через Блокнот или Проводник.
   Нажми **F5** — файл должен появиться. Удали тестовый файл и повтори F5.
5. Создай папку кнопкой **New folder**, переименуй тестовый файл и
   скопируй его через Drop Zone. Соответствующий каталог должен обновиться
   автоматически после завершения каждой операции.
6. Два раза быстро нажми **F5** на медленной тестовой папке. Результат
   старого запроса не должен перезаписать более новую загрузку.

**Ограничение:** это не стресс-тест миллионов файлов в одной папке.
Один снимок ограничен 100 000 элементами. Тесты не должны выполняться
на бесценных рабочих данных.

## 1.2. Инспектор при медленном диске и быстром выборе

1. Выбери большой текстовый файл: панель предпросмотра сначала
   показывает **Loading preview and history...**, затем отображает
   ограниченный фрагмент и историю.
2. Быстро переключись между несколькими файлами: после завершения
   фоновых задач не должны появляться данные от предыдущего файла.
3. Открой папку с сетевым/медленным диском и прокручивай файлы:
   отрисовка интерфейса не должна ожидать чтения истории.
4. Добавь комментарий к событию и проверь, что после сохранения он
   обновляется в инспекторе. При внешнем сохранении файла нажми
   **Refresh details**, чтобы перечитать его события.
5. Проверка производительности остаётся предварительной до запуска
   нативной Windows-сборки.

## 1.3. Escape без изменения файлов

1. Нажми F2 на тестовом файле, введи новое имя и нажми Esc.
   Переименование должно закрыться, исходный файл остаётся на месте.
2. Вызови Ctrl+Shift+N и нажми Esc: папка не создаётся.
3. Начни двухкликовое подтверждение Recycle, нажми Esc,
   затем Recycle ещё раз: это должно быть **новое первое подтверждение**.
4. Открой контекстное меню и поиск, по очереди нажми Esc.
   Окна закрываются без операций. Уже запущенная фоновая копия
   должна продолжаться, пока не выбрана отдельная Cancel copy.

## 1.4. Подсветка и отзывчивость

1. Наводи курсор на вкладки, команды, боковую панель и строки файлов:
   цвет подсветки должен меняться без мерцания.
2. Быстро прокрути папку с 5000 файлами — подсветка не должна
   снижать отзывчивость скролла или перечитывать список.
3. Выделенная строка остаётся читаемой при наведении.
4. Плавные переходы пока не считаются реализованными: в GPUI CE 0.2.2
   отсутствует API `transitions`, появившийся в более поздних исходниках.

## 1.4. Компактное окно и контекстные действия

1. Уменьши ширину окна: вкладки и длинная панель кнопок должны
   прокручиваться горизонтально, а не обрезать недоступные действия.
2. Включи Split. Нажми правой кнопкой по файлу **в правой панели**,
   затем Stage и Copy here (только тестовый файл). Назначение должно
   соответствовать активной правой панели, а не левой.
3. Вызови контекстное меню на папке справа, нажми Open.
   Должна открыться именно правая панель, сохраняя левую.
4. Начни двухкликовое подтверждение Recycle для одного тестового
   файла, затем выбери другой файл или вкладку. Старое подтверждение
   не должно применяться к новой цели.

## 1.3. Изменение размеров панелей мышью

1. Потяни вертикальный разделитель между боковой панелью и файловым
   содержимым, затем между файлами и правым инспектором.
   Ширина должна меняться без скачков и повторного сканирования диска.
2. Включи **Split**, потяни разделитель между левой и правой панелями.
   Навигация в каждой панели должна остаться независимой.
3. Переключи вкладки, затем включи поиск и вернись к файловому списку.
   Приложение не должно падать или оставлять пустые области интерфейса.
4. Переключись в **Miller Columns** и потяни разделитель между двумя
   соседними колонками. Обе ширины должны изменяться без повторного чтения
   каталога. При узком окне горизонтальная прокрутка должна сохраняться.
5. Переключись в обычный **List**: файл-лист должен занимать всю ширину.
   Вернись в Miller, затем переключи вкладки и Split; размеры не должны
   ломать компоновку или приводить к аварийному завершению.

## 2. Создание, переименование, контекстные действия

1. Зайди в `FM-test-A`, нажми **New folder**, введи `Испытание` и
   нажми **Создать**. Папка должна появиться.
2. Правой кнопкой нажми тестовую папку или файл. Должно открыться
   меню **Open / Stage to Drop Zone / Rename / Copy full path / Recycle**.
3. Нажми **Rename**, введи `Испытание_2`, затем **Переименовать**.
   Убедись, что первоначальная папка переименована, а содержимое не
   изменилось. Проверь **Undo last rename**.
4. Попробуй создать уже существующую папку с тем же названием.
   Программа должна отказаться и ничего не переписать.
5. Нельзя создавать `CON`, `NUL.txt`, папки с символами `/\` и
   другие недопустимые имена Windows.

## 3. Drag-and-drop и папки

1. В `FM-test-A` создай папку `Данные`, внутри файл `sample.txt`,
   подкаталог `Подкаталог` с файлом `model.txt` и пустую папку.
2. Перетащи `Данные` на **Drop Zone** в левой панели: это только
   подготовка к действию. Оригинал должен оставаться на месте.
3. Открой `FM-test-B` и нажми **Copy here**. Должны скопироваться
   оба файла, вложенная и пустая папки. Исходная папка остаётся на месте.
4. Повтори копирование с тем же именем. Должен быть отказ; существующий
   каталог `FM-test-B\Данные` должен остаться неизменным.
5. Проверь, что можно перетаскивать также **отдельные файлы**.
   Пока поддерживается **перетаскивание внутри приложения**, а не
   импорт из Проводника Windows.
6. Для проверки отмены подготовь отдельный большой тестовый файл,
   начни копирование, затем нажми **Отменить передачу**. При успешной отмене
   файл с окончательным именем не появляется; если копирование
   закончилось раньше отмены, файл должен быть целым.
   **Внимание:** при аварийном закрытии могут остаться временные
   `.fm-partial` — не используй важные данные для этого теста.

## 3.1. Проверка ссылок и источников

1. Если на тестовой машине есть symlink или junction к рабочему файлу,
   попытка положить **ссылку** в Drop Zone должна отказать, не
   добавляя автоматически реальный файл-цель.
2. Во время пробной копии измени содержимое источника **во внешней
   программе**. Если изменения обнаружены, копия не должна
   публиковаться с конечным именем.
3. Для больших и вложенных папок прежний принцип сохраняется:
   копия становится видимой только после полного переноса данных
   из временной папки.

## 3.2. Перемещение в другую панель (только тестовые данные)

1. Создай в `FM-test-A` файл `move-me.txt`, а в `FM-test-B` оставь свободное место.
2. Добавь файл в Drop Zone, перейди в `FM-test-B`, нажми **Move here**.
   Файл должен оказаться только в B; проверь запись в SQLite-журнале.
3. Для одного переноса проверь **Undo** — файл возвращается в A.
4. Создай в B файл с тем же именем, но иным содержимым. Повтори Move:
   файл B не заменяется, файл A остаётся целым, ошибка видна в интерфейсе,
   неудачный путь остаётся в Drop Zone.
5. Между разными дисками выполняется проверяемая копия и перенос исходника
   в Корзину. Подробная проверка — ниже; прямого постоянного удаления нет.
6. Если добавить несколько файлов и один вызовет конфликт, успешные
   переносы допускаются; Ctrl+Z отменяет сохранённые квитанции группы.
   Проверь оба каталога; неудачные элементы должны остаться в Drop Zone.

## 3.3. Перенос между томами (новый код, Windows smoke ещё не выполнен)

Использовать только специально созданные тестовые данные на двух локальных
томах; нужна доступная Корзина. Это отдельная проверка реального EXE.

1. Перенеси файл и дерево с пустым вложенным каталогом с C: на другой том.
   Цель должна быть целой; после фазы «Проверка копии» исходник оказывается
   в Корзине. Ctrl+Z сначала восстанавливает исходник, затем убирает копию.
2. На NTFS добавь файловый ADS (`Set-Content -LiteralPath <путь> -Stream notes
   -Value test`), перенеси файл; проверь `Get-Content -Stream notes` у цели.
   Перенос на том, потерявший ADS, должен отказать после создания копии:
   исходник остаётся, опубликованная копия сохраняется, оба пути видны.
3. Каталог с ADS: если существующий copier не перенёс поток каталога,
   проверка должна отказать и сохранить исходный каталог. Не ожидать
   успешного переноса неподдерживаемого потока.
4. Отмени большой перенос во время копирования и во время проверки.
   До публикации цели её окончательное имя не появляется; после публикации
   целая копия сохраняется, исходник не отправляется в Корзину.
5. Измени цель после успешного переноса; Ctrl+Z должен отказать и сохранить
   изменения. Займи исходное имя — никакой перезаписи при Undo.
6. Проверка разработчиком частичного Undo: отказ записи фазы/очистки после
   восстановления сохраняет квитанцию этапа и оба пути в ошибке/журнале.
   Повтор убирает только копию. Если восстановленный исходник пропал или
   изменился, повтор сохраняет копию. Этот отказ уже покрыт core-тестами.
7. Заверши процесс на фазе проверки, запусти снова: журнал показывает этап,
   источник/назначение; автоматического повторения или очистки нет.
   Неудачные действия с записанной фазой тоже остаются в диагностике.

## 4. История и поиск

### Сетевые папки, закрытый доступ, журнал

1. Открой `\\сервер\ресурс` и папки внутри: видны все папки, как в
   Проводнике, включая те, к которым нет доступа; нет пометки «Показаны не
   все элементы». Список большой сетевой папки открывается быстро.
2. Открой папку без прав доступа: сообщение «Не удалось открыть папку» только
   в её колонке; после перехода в другую папку ничего красного не остаётся.
   Над колонкой, за которой Windows не даёт следить, — серая строка
   «Без автообновления — F5 обновит».
3. Сетевые папки (`\\сервер\…` и подключённые диски) не подписываются на
   уведомления Windows, а перечитываются раз в 5 секунд. Походи 10–15 минут
   по глубоким папкам ресурса в нескольких панелях и вкладках: Проводник
   должен по-прежнему открывать те же папки. Новый файл, сохранённый на
   ресурсе с другого компьютера, появляется в списке в течение ~5 секунд.
4. Журнал включён сразу после запуска («Записывается»). Измени файл в Word
   в открытой папке: в «История изменений» появится «Изменён» с твоей
   учётной записью. «Остановить» приостанавливает запись до повторного
   включения.

### Раскладка как в Atlas

1. Боковая панель на всю высоту: за шапку «Filemanager» окно перетаскивается,
   кнопка рядом скрывает панель (Ctrl+B возвращает). При растягивании окна
   ширина боковой панели не меняется.
2. Строка навигации: только ← → ↑ и путь. Нижняя строка: лупа слева (Ctrl+F)
   открывает поле фильтра, Esc закрывает; справа новая папка, разделить,
   скрытые (Ctrl+.), список, колонки.
3. Ctrl+K или Ctrl+Shift+P: палитра с разделами и клавишами; стрелки вниз
   до «Вид» — список прокручивается за выбором. Окно появляется плавно,
   открытие папок и колонок — мгновенно.

### Версии файлов

1. В тестовой папке сохрани `Отчёт.docx`, затем «Сохранить как»
   `Отчёт_v_1_5.docx` и `Отчёт_v_1_6.docx`. Выбери последний, Ctrl+I: блок
   «Версии · 3» — 1.6, 1.5, Исходный; щелчок по строке выбирает файл.
2. Включи «Записывать историю», сохрани из Word `Отчёт_v_1_7.docx`. В истории
   появится «Новая версия» с пометкой «Версия 1.7»; у 1.6 видны записи и 1.5.
3. `Отчёт_v_1_6.pdf`, `Смета_v_1_6.docx`, `Server2.txt` в версии не попадают.

### Проверки пакета 4: документы и миниатюры

1. Выбери PNG/JPEG, небольшой PDF, Word/Excel/PowerPoint. Текст/история должны
   появляться независимо от миниатюры. Быстро переключай A/B/A: не должно
   оставаться изображения предыдущего файла или задержки прокрутки списка.
2. Для документа нажми «Просмотреть документ». Проверь содержимое, прокрутку,
   клавиатуру и изменение размера отдельного окна. Листание зависит от
   установленного Windows provider. Файл должен остаться неизменным.
3. Нет provider: должно появиться понятное сообщение; менеджер работает,
   документ открывается обычной командой. Проверить также 32-bit Office:
   helper 64-bit не загружает несовместимый in-process provider.
4. Открой другой документ: старое preview закрывается. «Закрыть предпросмотр»
   доступно при другой/пустой/групповой выборке. Закрой менеджер: его preview
   процесс не должен остаться. При зависшем provider кнопка тоже закрывает child.
   Закрой окно предпросмотра его собственным крестиком: в течение секунды
   статус менеджера должен смениться на «Окно предпросмотра закрыто», кнопка
   «Закрыть предпросмотр» — исчезнуть (исправление 11.10, ранее статус залипал).
5. Документ более 64 МБ отказывает без загрузки; исходник остаётся целым.
   Проверь повреждённый файл и PNG с огромными dimensions при малом размере.
   Не допускаются зависание/рост памяти основного процесса; thumbnail timeout 5s.
6. В LOCALAPPDATA/Filemanager/thumbnails испорть тестовый PNG cache, выбери
   файл снова: валидная миниатюра пересоздаётся либо остаются сведения о файле.
   Накопи более 256 разных миниатюр; после обслуживания кэш ограничен 256/64 МБ.

### Проверки пакета 3: массовое переименование

1. В отдельной тестовой папке создай `отчёт.txt`, `notes`, папку `эскиз`.
   Выдели их и нажми F2. Для `{stem}-{n}{ext}` проверь список новых имён,
   затем примени. Ctrl+Z должен восстановить все исходные имена.
2. Попробуй `CON`, одинаковое имя для двух файлов и существующее имя.
   Строки должны показать ошибки, применение должно быть недоступно.
3. Быстро меняй шаблон, закрой окно Escape и открой снова. Предпросмотр
   должен соответствовать текущему полю; закрытый запрос не должен примениться.
4. После расчёта предпросмотра измени один исходный файл через Проводник
   либо создай одну из будущих целей. Применение должно отказаться от этого
   элемента; занятый файл должен сохранить содержимое. Уже выполненные
   элементы можно отменить общей командой; проверь записи панели операций.
5. На большой тестовой группе проверь общую отмену и правильное название
   операции «Переименование». Проверяй только копии тестовых данных.
6. Проверь Unicode-конфликт: `Σ.txt` и `ς.log`, шаблон `{stem}.renamed`.
   Применение должно блокироваться. В группе более 30 элементов спровоцируй
   два ранних отказа и последующие успехи: оба отказа должны остаться
   в отдельном результате группы даже после обновления панели операций.
7. После применения выделение и сообщения показывают обычные пути
   (`C:\...`), без префикса `\\?\`. Пути в предпросмотре — тоже.

### Проверки пакета 2: замена и панель операций

На тестовых файлах с разным содержимым и одинаковыми именами:

1. Выбрать «Заменить файлы — прежние в Корзину». Прежний файл должен быть
   в Корзине, новый — в назначении. Ctrl+Z восстанавливает прежний файл;
   исходник Copy сохраняется, исходник Move возвращается обратно.
2. Каталог нельзя заменить/слить этой кнопкой. «Сохранить оба» и «Пропустить»
   продолжают действовать отдельно. Заменить файл самим собой нельзя.
3. Изменить новый файл после успешной замены — Undo должен отказать,
   сохранив изменения. Старый файл остаётся в Корзине.
4. Отмена после отправки прежнего файла в Корзину может оставить его имя
   свободным. Ошибка должна сообщить оба пути и точный recycle identity.
   Восстановление в этой ситуации ручное; автоматического повтора нет.
5. Открыть панель операций во время передачи: число обработанных заданий,
   текущий файл, этап и кнопка отмены видны. Список последних 30 записей
   обновляется, содержит успешные и ошибочные задания. Закрыть/открыть
   панель быстро — старый запрос не должен переписать новый список.
6. На Windows проверить поздний конфликт восстановления при Move и
   прерванный Undo: фактический путь уже восстановленного исходника и
   точная квитанция прежнего файла должны сохраниться в диагностике.

Windows runtime этих изменений ещё не проверен. Core-тесты проверяют
последовательность этапов, настоящую Корзину Linux и сохранённое состояние,
но не воспроизводят Windows Shell/UI.

1. В `FM-test-A` нажми **Watch folder**. Открой `sample.txt`
   в Блокноте и сохрани изменение.
2. Выдели файл, справа выбери нужное событие **Select this save**,
   введи автора и комментарий, нажми **Save comment**.
   Повторно выбери то же событие: введённые поля должны сохраниться.
3. Создай файлы `Фундамент.txt` и `Расчётная_модель.xlsx`. В строке
   поиска набери `фун`, затем `расмод` — должны находиться соответствующие
   имена. Проверь `Ctrl+F` и закрытие результатов через **Close results**.
4. Оставь поиск открытым. Создай через Блокнот файл `Новый_отчёт.txt`
   внутри `FM-test-A`. Через несколько секунд он должен появиться в
   результате поиска `отчёт` **без ручного Refresh index**. Переименуй
   его в `Новый_акт.txt` средствами Windows. Старое имя должно исчезнуть,
   а новое — находиться поиском `акт`.
5. Создай подпапку с несколькими файлами, затем переименуй её и удали
   через обычный Проводник (только в тестовом каталоге). Проверь, что
   старые пути пропадают из результатов, а новые появляются.
6. Закрой программу, создай ещё один тестовый файл через Проводник,
   снова открой Filemanager и активируй поиск. Сохранённый SQLite-индекс
   загрузится сразу, затем фоновая сверка должна подхватить изменения,
   сделанные за время закрытия.
7. Нажми **Refresh index**. Это ручная полная перепроверка на случай,
   если Windows или сетевая папка пропустила уведомления.
8. Проверь, что создание и обновление индекса не меняет реальные файлы.
   В базе `%LOCALAPPDATA%\\Filemanager\\file-index.sqlite3` хранятся
   только имена/пути файлов; старых версий документов нет.
4. В журнале сохраняется **только информация об изменениях**.
   Предыдущие версии документов восстановить нельзя.

## 5. Корзина и защита от изменения после подтверждения

1. Выбери тестовый файл, нажми **Recycle** один раз и затем измени
   содержимое файла через Блокнот. Второе нажатие должно **отказаться**
   отправлять изменившийся файл в Корзину.
2. Для другого тестового файла дважды нажми **Recycle**, не изменяя его
   между нажатиями. Проверь, что он попал в Корзину Windows.
3. Переименуй тестовый файл, затем измени содержимое под новым именем.
   Нажми **Undo last rename**: программа должна отказаться выполнять
   отмену, так как файл назначения уже изменился.

## 5.1. Безопасная отмена и внешние сохранения

Проверять на временных тестовых данных после общей сборки Windows.

1. Скопируй тестовый файл, затем измени **копию** внешним редактором.
   Ctrl+Z должен отказать и сохранить изменения. Создай новую папку,
   добавь в неё документ — отмена создания папки также должна отказать.
   Для скопированной папки проверь новый и изменённый вложенный документ.
2. Удали `report.pdf` и `report.docx` с разным содержимым и одинаковым
   отображаемым именем при скрытых расширениях. Отмена должна вернуть
   каждый конкретный файл. Повтори с двумя удалениями одного пути,
   создавая другой файл между удалениями: старый Undo не выбирает новый.
3. После удаления займи исходное имя новым тестовым файлом. Ctrl+Z
   отказывает без перезаписи; после освобождения имени повторный Ctrl+Z
   восстанавливает оригинал. Успешные элементы частичной отмены не повторяются.
4. Оставь папку открытой в Filemanager, создай, переименуй и удали файл
   через Проводник. Список обновляется без повторного открытия. Выбери
   документ, включи историю и сохрани его во внешнем редакторе:
   инспектор показывает новые метаданные и событие после записи в SQLite.
5. Для Copy проверь дополнительный поток NTFS (`file.txt:notes`), время
   изменения и readonly/hidden-атрибуты. Сначала проверь отдельный файл,
   затем файл внутри копируемой папки. Отмена большой копии не публикует
   недокопированную папку даже во время заключительного обхода.

Не найденный идентификатор Корзины отключает безопасную отмену этого
действия и показывается явно. Если Windows предлагает безвозвратное
удаление вместо Корзины, откажись; программа сохраняет системное предупреждение.
При позднем конфликте имени восстановленный файл может получить свободное
имя: интерфейс показывает его фактический путь, а журнал сохраняет его.

## 6. Журнал операций и аварийное восстановление

**Автоматическая проверка нескольких экземпляров:** unit test
`cannot_mark_another_windows_running_job_as_interrupted` удерживает
блокировку одного окна, затем проверяет, что другой экземпляр не
меняет `running` на `interrupted`. После освобождения блокировки
пометка становится допустимой, **без повтора файловых действий**.

**Автоматическая проверка CLI:** `cargo test -p filemanager-cli --all-targets`
проверяет, что `fmctl` пишет запись в `operation-queue.sqlite3`, а при
повреждённой базе отказывает в операции и не затрагивает файлы.
Промежуточное ручное тестирование пользователем не требуется.

0. Открой два экземпляра Filemanager. На копии **большого тестового
   файла** начни Copy в первом окне и попытайся Copy или Recycle
   **другого тестового файла** во втором. Пока операция первого окна
   активна, второй экземпляр должен отказаться и сохранить оба файла.
   После завершения повтори операцию вручную — она должна выполниться.
   Проверь, что конфликт не создаёт бесконечного ожидания и не включает
   автоматический повтор.

1. На тестовых файлах выполни Copy, New folder и Rename. Открой
   **Operation review** в боковой панели. Нормально завершённые
   действия не должны отображаться как незавершённые.
2. Во время копирования **только большого тестового файла** (не
   рабочей модели!) аварийно закрой процесс Filemanager средствами
   диспетчера задач. После перезапуска открой Operation review.
   Запись `running` или `interrupted` должна остаться в SQLite.
3. Убедись, что после перезапуска программа **не повторяет** копирование,
   удаление или перемещение сама. Сверь реальные пути в Проводнике.
   Повтор возможен только после ручного решения пользователя.
4. Если SQLite-журнал операций не открывается, любые кнопки
   изменения файлов должны показывать отказ, а не выполнять действие
   без регистрации. Не удаляй реальную БД для теста: этот сценарий
   покрывается Rust unit test с повреждённой **временной** SQLite.
5. Файл журнала:
   `%LOCALAPPDATA%\\Filemanager\\operation-queue.sqlite3`.
   Журнал содержит только типы действий, пути и статусы — без
   содержимого документов и без резервных версий.

## Если обнаружена ошибка

Пришли скриншот окна или красный шаг лога GitHub Actions. Укажи,
какой пункт выполнял и что произошло. До подтверждения тестов
не используй программу для удаления или переноса единственного экземпляра
важных документов.

Ограничения: автоматическое обновление SQLite через notify реализовано в
коде, но на Windows пока не проверено. Это не Windows USN Journal: при
переполнении очереди или ошибке выполняется повторная сверка. Наблюдение
обновляет видимые папки и отдельно поисковый индекс при открытом Filemanager; фонового Windows
сервиса пока нет. Окончательная оптимизация сверхбольших каталогов, воспроизведение видео,
перетаскивание из Проводника и восстановление файловой очереди после сбоя
пока не реализованы.
