# Изолированный предпросмотр

Пакет 4: читать PDF/Office без запуска редактора, видеть изображения и
миниатюры, сохранять отзывчивость менеджера. Rust/GPUI остаются; облаков,
исторических версий/содержимых и новых декодеров документов не добавляем.

Выбран отдельный нативный preview HWND в дочернем экземпляре того же EXE,
запускаемом кнопкой «Просмотреть документ». Windows выбирает зарегистрированный
IPreviewHandler по расширению. STA, read-only Stream/File/Item initialization,
SetWindow/DoPreview, resize/Unload/CoUninitialize. Нет обработчика — понятная
ошибка и возможность открыть документ обычной командой. Не устанавливаем Office.
Сравненные альтернативы: встроенный HWND усложняет GPUI/focus и оставляет
сторонний код в процессе; собственные PDF/Office декодеры расширяют стек.

Один дочерний preview на окно менеджера; повторная команда заменяет предыдущий.
Есть кнопка закрытия preview из менеджера, даже если обработчик завис. При
закрытии менеджера процесс уничтожается. Windows Job Object: 256 MiB process
memory, kill-on-close. Это ограничение ресурсов, не security sandbox.
Документы до 64 MiB: pdf/doc/docx/xls/xlsx/ppt/pptx/rtf/odt/ods/odp.
Проверка пути/типа/размера на worker; ссылки отвергаются, исходник не меняется.

Shell миниатюры тоже считаются в дочернем процессе: timeout 5 секунд,
тот же Job limit. Edge 1..512; выходные width/height <= edge, checked RGBA
allocation <= 1 MiB. Отказ/повреждённый cache не идёт в GPUI decoder.
PNG cache <=256 изображений/64 MiB при обслуживании, временные файлы уникальны.
Прямое декодирование исходного сжатого изображения в GPUI убирается.

Inspector: текст/history не ждут Shell. Не более одного worker details и
одного thumbnail worker на окно, выбор последних данных coalesced;
generation/path guards не дают показать устаревший результат. Старое изображение
очищается сразу. Все filesystem/SQLite/COM проверки вне UI.

Runtime Windows/GPUI/installed providers проверяются в итоговом Windows пакете;
cross-check здесь устанавливает только компилируемость, не рабочий preview.
