# Конфликты и панель операций

Цель: продолжить пакет 2 общего плана без смены Rust/GPUI и без хранения
старого содержимого документов. Пользователь разрешил последовательное
исполнение и push рабочей ветки без дополнительных запросов.

Для совпавших имён добавить явную «Заменить файлы». Это не silent overwrite:
подтверждённый старый файл проверяется снимком и отправляется в Корзину,
после чего существующий no-clobber Copy/Move публикует новый результат.
Если объект изменился после подготовки, выполнение отказывает. Отказ после
переноса старого файла сохраняет исходник/опубликованный результат и сообщает
путь старого файла в Корзине; диагностика не запускает автоматический replay.
Без точного recycle token продолжение запрещено. Отмена проверяется до
мутаций. Замена каталогов/слияние деревьев пока запрещены: кнопка явно про файлы.

Undo сначала отменяет входящий Copy/Move, затем восстанавливает старый файл
по точной квитанции. Разделяемое состояние хранит завершённую первую стадию:
если восстановление старого файла отказало, повтор не удаляет новый объект
второй раз. Занятое исходное имя не перезаписывается; поздний конфликт Shell
сообщает фактический путь. Защита метаданных не устраняет внешние TOCTOU-гонки.

Панель операций показывает последние 30 записей, включая успешные/неудачные,
статус, этап, источник, назначение и ошибку. SQLite читается только в фоновой
задаче; пока панель открыта, обновление раз в секунду. Это диагностика и
наблюдение, не автоматическое продолжение после аварии.
Прогресс передачи показывает текущий путь и число обработанных заданий;
Copy/Move пользуются общей отменой. Чтение прогресса не обращается к диску.

Варианты: прямая перезапись отвергнута (нет безопасного Undo); полнофункциональный
транзакционный staging со слиянием каталогов отложен (иной объём/семантика).
Выбран минимальный путь с Корзиной и существующим copier. В случае ошибки
пустое место прежнего файла может потребовать ручного восстановления.
Windows EXE/два тома проверяются отдельной редкой ручной сборкой.
