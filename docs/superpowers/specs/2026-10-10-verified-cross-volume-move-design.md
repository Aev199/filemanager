# Проверяемый перенос между томами

## Требования

Расширяем существующий `Action::Move`, используемый GUI и CLI. На одном томе
сохраняем `MoveFileW`; только Windows ERROR_NOT_SAME_DEVICE запускает новый путь.
Rename не превращается в Copy+Delete. Ошибки доступа/занятые имена не дают fallback.

На другом томе: снять снимок исходника → существующее staging-копирование
без перезаписи → сравнить содержимое каждого файла и дополнительные потоки
NTFS → повторно проверить снимки исходника/копии → отправить исходник в Корзину.
Постоянное удаление напрямую не выполняем. Системное предупреждение о
невозможности Корзины сохраняется; защита не является файловой транзакцией.

Сравнение потоковое, буфер 256 КБ; старое содержимое/хеши не сохраняются.
Сравнивается состав дерева и список/размер/содержимое потоков. Неподдерживаемые
или потерянные потоки блокируют удаление исходника. После публикации копии
любой отказ/отмена сохраняет её и исходник с ясным сообщением о двух путях;
автоматической очистки опубликованной копии и автоматического повтора нет.

Undo проверяет неизменность копии, восстанавливает точный объект исходника из
Корзины и затем отправляет созданную копию в Корзину. Частичный Undo сохраняет
стадию восстановления в разделяемой квитанции в памяти, чтобы повтор не
использовал уже израсходованный идентификатор Корзины. При позднем конфликте
показывается фактический путь восстановления. Без точной квитанции — барьер Undo.

SQLite сохраняет фазу до каждого потенциального изменения. Отказ записи
фазы не позволяет начать следующую мутацию. После аварии — диагностика,
не автоматическое возобновление. Для старой БД нужна совместимая миграция.

## Компоненты

- `copy_verification.rs`: сравнение деревьев/потоков, отмена, Windows stream handles.
- `cross_volume_move.rs`: порядок шагов и разделяемое состояние Undo.
- `operations.rs`: fallback Move, квитанция, `TransferPhase`, контекст журнала.
- `operation_journal.rs`: колонка `phase`, checkpoint, показ незавершённой фазы.
- Desktop: существующая кнопка отмены действует на Copy/Move; прогресс показывает
  копирование или проверку. Тяжёлые действия остаются на background executor.

## Ограничения

Читающий guard Windows запрещает конкурирующих писателей во время чтения
файла, но не блокирует весь внешний мир до Shell recycle. Снимки — метаданные,
между последней проверкой и Shell остаётся окно гонки. Не добавляем постоянный
Undo после перезапуска. Программа может отказать на открытом пишущим приложением
файле или файловой системе без необходимых возможностей; сохранность важнее
скрытого обхода проверки. Проверка атрибутов/потоков на реальных Windows-томах
не заменяется Linux-тестами или cross-check компиляции.
