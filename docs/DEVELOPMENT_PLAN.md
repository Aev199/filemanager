# План доработки этапов 1–3

Цель: довести Rust + GPUI файловый менеджер до повседневной работы на Windows.
Проверка пользователем — после готового пакета, а не после каждого коммита.
Push в `feat/native-gpui-foundation` разрешён; в `main` пока не вливаем.
Сборки EXE остаются ручными и редкими. Старые содержимые документов не храним.

| Пакет | Результат и проверка | Статус |
|---|---|---|
| 1. Перенос между дисками | Copy → сравнение содержимого/потоков → Корзина исходника; отмена, фазы SQLite, сохранность при отказе | Код и локальные проверки готовы; Windows smoke ожидает |
| 2. Конфликты и очередь | Явная замена файлов с сохранением прежнего в Корзине, наблюдение за последовательной очередью, прогресс/отмена, диагностика частичных действий | Код и локальные проверки готовы; Windows smoke ожидает |
| 3. Массовое переименование | Предварительный список старых/новых имён, проверка конфликтов и запрещённых имён, безопасное исполнение и Undo | Код и локальные проверки готовы; Windows smoke ожидает |
| 4. Предпросмотр | Просмотр PDF/Office через Windows handlers, изображения и миниатюры, ограничения памяти и фоновые запросы | Код и локальные проверки готовы; Windows providers/UI smoke ожидает |
| 5. Интерфейс | Палитра команд, закрепление вкладок, выделение рамкой, настройки; сохранить клавиатурную навигацию и отзывчивость | Код и локальные проверки готовы; Windows UI smoke ожидает |
| 6. Итоговая проверка | Одна общая Windows-сборка, тестовые каталоги/два тома, сохранения Word/Excel/CAD, сеть, несколько окон, скриншоты | Идёт: см. [FINALIZATION_PLAN](FINALIZATION_PLAN.md) |

Большие каталоги и недоступные диски проверяем в соответствующих пакетах.
История содержит дату/время обнаружения, учётную запись наблюдателя и вручную
заданные автор/комментарий. Точное автоматическое определение автора сохранения
не обещаем. Рекурсивный постоянный сервис при закрытом окне, USN/MFT,
цветовые метки, облака/FTP/плагины и отдельный этап 4 не являются обязательными.

## Порядок исполнения

Каждый пакет: спецификация → тесты отказов → реализация → проверки core/CLI
и Windows workspace → независимое ревью → push и обновление документации.
Готовность кода и проверку EXE отмечаем отдельно. Не включаем автоматический
replay после аварии и не выдаём наличие миниатюры за полный просмотр документа.

Детальный план первого пакета:
[verified-cross-volume-move](superpowers/plans/2026-10-10-verified-cross-volume-move.md).

Следующий этап — панели со своими вкладками, как в Atlas:
[pane-groups](superpowers/plans/2026-10-11-pane-groups.md).
