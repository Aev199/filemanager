# Filemanager — критерии завершения этапов 1–3

**Цель:** собственный нативный Windows-файловый менеджер по мотивам UX Atlas:
Rust + GPUI, быстрый SQLite-поиск, портативный EXE. Без облачных дисков,
FTP и плагинов. Это не копирование чужого исходного кода.

Важно: наличие функции **в исходном коде** не означает, что она готова.
Пункт считается завершённым, только когда свежая Windows-сборка прошла
тесты и проверен EXE на тестовых каталогах.

## Дополнение: надёжность очереди (текущая итерация)

- `operation-queue.sqlite3` хранит исключительно сведения об операции:
  тип, пути, даты, состояние (`queued/running/done/failed/interrupted`)
  и короткую ошибку, **но не содержимое файлов**.
- Очередь в GPUI пишет намерение и состояние `running` **до**
  изменения файлов. Если SQLite недоступна, файловое действие
  блокируется; это проверяется отдельным тестом.
- Действия из интерфейса проходят через один audited executor:
  Copy, Create Folder, Rename, Recycle и Undo. В боковой панели
  `Operation review` можно прочитать незавершённые записи и проверить
  источники/приёмники. Открытие обзора ничего не изменяет на диске.
- **Автоматического восстановления/повтора нет.** При сбое состояние
  `running` неопределённо: операция могла частично или полностью
  пройти. На общей системе/при нескольких экземплярах `running`
  может означать действие в другом активном экземпляре.
- Нужны: идентификаторы экземпляров, защита параллельных очередей,
  хранение прогресса/контрольных данных и процедура ручного восстановления.
  До этого безопаснее отказ, чем неявный повтор.

| Функция | Исходный код | Проверка EXE |
|---|---|---|

| Переименование, создание папки и отправка в Корзину | Да, через очередь | Ожидает |
| Drop Zone и внутреннее перетаскивание | Базовая реализация | Ожидает |
| Отмена активного копирования | Да, кооперативная | Ожидает |
| Undo переименования | Да, с проверками | Ожидает |
| Move между панелями на одном томе | Через Drop Zone и SQLite-очередь | Ожидает |
| Move между разными томами | Не готово; автоматического copy+delete нет | — |
| Drag-and-drop из/в Проводник Windows | Не готово | — |
| SQLite-журнал жизненного цикла операций и просмотр неопределённых задач | В коде; без автоматического повтора | Ожидает |\n| Полноценное восстановление или управляемый безопасный повтор после сбоя | Не готово | — |

**Критерий:** повреждённый, изменённый или конфликтующий файл не может
быть без предупреждения заменён. Удаление проходит через Корзину, а
копирование/перемещение — только через проверенную очередь.
Крупная операция допускает отмену, ошибки отображаются пользователю.

- [ ] Гарантированное отслеживание выбранных папок при закрытом окне
  (отдельный безопасный наблюдатель, опционально).

**Никаких копий старых файлов, бинарных версий, дельт или отката содержимого.**
Имя автора может вводиться вручную и не доказывает фактического авторства.
История не заменяет резервное копирование.

## Правила сборки и релиза

1. Сборка Windows EXE остаётся **только по ручному запуску Actions**,
   без on-push и on-PR триггеров, чтобы экономить лимит бесплатного GitHub.
2. До первого нового зелёного CI после большого пакета изменений
   работа остаётся в черновом PR и не сливается в `main`.
3. После сборки — [проверка на одноразовых тестовых папках](SMOKE_TEST.md).
4. Если сборка не проходит, сначала исправляем ошибки компиляции,
   а не добавляем ещё несколько фич поверх непроверенного кода.
5. Запуск важных файловых операций на единственных экземплярах
   документов запрещён до полноценного Windows-тестирования.

**Текущий статус:** успешная CI-сборка №2 относится только к раннему
коммиту `1e4c6f8`. Весь последующий код, включая виртуализацию списка
и автообновление поиска, ещё должен пройти Windows-сборку.
